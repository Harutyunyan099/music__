# muzzz

Անձնական երաժշտական web app՝ քո լոկալ ֆայլերը + YouTube որոնում, հավաքածու,
սիրածներ, վերջին լսածներ, մշտական նվագարկիչ և **My Wave** (Моя волна) —
անձնական ալիք, որը կառուցվում է քո իրական լսածից։

Ամեն ինչ աշխատում է քո համակարգչում։ YouTube API բանալին **երբեք** չի հայտնվում
frontend-ում՝ բրաուզերը խոսում է միայն քո սեփական backend-ի հետ։

---

## 1. Արագ սկիզբ

```bash
# 1. բանալին
cp .env.example .env
#    բացիր .env-ը և գրիր՝ YOUTUBE_API_KEY=քո_բանալին

# 2. գործարկում
python3 server.py          # կամ՝ start-windows.bat / ./start-mac-linux.sh
```

Բացվում է `http://localhost:8000`։

Առանց բանալու էլ ծրագիրն աշխատում է՝ լոկալ 20 երգը, հավաքածուն, սիրածները,
նվագարկիչը և ալիքը (լոկալ ֆայլերի հիման վրա)։ Որոնման բաժինը այդ դեպքում
ցույց է տալիս հստակ հաղորդագրություն, ոչ թե սխալ։

**YouTube Data API v3 բանալի ստանալ**՝ [console.cloud.google.com](https://console.cloud.google.com) →
նոր project → *APIs & Services* → *Enable APIs* → **YouTube Data API v3** → *Credentials* → *API key*։

## 2. Ճարտարապետություն

```
Browser ──► /api/search ──► server.py ──► YouTube Data API v3
                              │  (բանալին այստեղ է՝ .env / env var)
Browser ◄── մաքուր JSON ◄─────┘
```

- `.env`-ը `.gitignore`-ում է. բանալին repo չի ընկնում։
- Backend-ը երբեք չի վերադարձնում YouTube-ի raw պատասխանը (այն կարող է բանալին պարունակել)։
  Սխալները թարգմանվում են կարճ կոդերի՝ `no_key`, `quota`, `bad_key`, `network`, `upstream`։
- Պատասխանները cache-վում են 10 րոպե՝ quota-ն չվատնելու համար։

### Backend endpoints

| Endpoint | Ինչ է անում |
|---|---|
| `GET /api/status` | կա՞ բանալի (frontend-ը դրանով է որոշում՝ որոնումը միացնել թե ոչ) |
| `GET /api/search?q=&pageToken=&order=&limit=` | YouTube search.list + videos.list միասին՝ տևողությամբ և դիտումներով |
| `GET /api/videos?ids=` | կոնկրետ video-ների տվյալները |
| ամեն ինչ մնացած | ստատիկ ֆայլեր՝ **Range** headers-ի աջակցությամբ (լոկալ երգերում seek անելու համար) |

## 3. Ֆայլերը

| Ֆայլ | Ինչ է |
|---|---|
| `index.html` | app shell՝ sidebar, mobile tabbar, player, now playing, modals |
| `style.css` | ամբողջ դիզայնը (գույները՝ `:root`-ում, night/day թեմաներ) |
| `store.js` | localStorage + IndexedDB. collection, favorites, recent, wave history, prefs |
| `api.js` | backend client՝ cache, abort, սխալների նորմալացում, YouTube title→artist parsing |
| `player.js` | մեկ նվագարկիչ երկու աղբյուրի համար՝ լոկալ `<audio>` և YouTube IFrame Player |
| `wave.js` | My Wave-ի recommendation engine |
| `i18n.js` | հայերեն / անգլերեն / ռուսերեն |
| `app.js` | routing, views, որոնում, player UI, ադմին պանել |
| `server.py` | ստատիկ սերվեր + YouTube proxy |
| `songs.json`, `*.m4a`, `*.jpg/svg` | քո լոկալ երգերը (չեն փոխվել) |

## 4. Ինչպես է աշխատում My Wave

1. **Signals** — ալիքը կշռում է կատարողներին ըստ՝ սիրածներ (×5) → վերջին լսածներ (×4)
   → հավաքածու (×2) → լոկալ ֆայլեր (×1)։
2. **Ընտրություն** — կշիռներով պատահական ընտրվում է կատարող (վերջին 2-ը բացառվում են՝
   որ նույն artist-ը անընդմեջ չգա), նրա անունով կատարվում է YouTube որոնում,
   արդյունքները cache-վում են 30 րոպե։
3. **Խառնում** — ~25% դեպքերում ալիքի մեջ մտնում է քո լոկալ ֆայլերից մեկը։
4. **Կրկնությունների բացառում** — վերջին 120 նվագարկվածը և skip արածները չեն առաջարկվում։
5. **Ավտոմատ շարունակություն** — երգը վերջանալիս `Player.onEnded` → `Wave.next()` →
   հաջորդը միանում է ինքնուրույն. հերթը միշտ լցված է 4 երգով։
6. **Skip / Don't recommend** — երգը գնում է skipped ցուցակ և այլևս չի հայտնվում։
7. **Դատարկ վիճակ** — եթե ոչ մի signal չկա, ցուցադրվում է onboarding + «Գտնել երաժշտություն»
   կոճակը։ Եթե API-ն անջատված է, ալիքը շարունակում է աշխատել լոկալ ֆայլերով։
8. Ամեն երգի կողքին գրված է՝ **ինչու** է առաջարկվել («Քանի որ լսում ես X»)։
   Ժանր չի հորինվում — YouTube API-ն այդ տվյալը չի տալիս։

## 7. Ինչ պետք է իմանաս

- **Երգերը չեն ներբեռնվում YouTube-ից։** Նվագարկումը կատարվում է YouTube-ի պաշտոնական
  IFrame Player-ով (embed), ինչպես պահանջում են նրանց կանոնները։ Ձայնի էքվալայզերն
  աշխատում է միայն լոկալ ֆայլերի համար՝ embed-ի ձայնին հասանելիություն չկա։
- Որոշ տեսանյութեր սեփականատերը արգելում է embed անել. այդ դեպքում ալիքը ինքնաբերաբար
  անցնում է հաջորդին։
- YouTube-ի `search.list`-ը արժե **100 quota unit**, օրական լիմիտը լռելյայն 10 000 է
  (≈100 որոնում)։ Դրա համար կա debounce (420ms), cache և pagination։
- GitHub Pages-ի վրա որոնումը **չի աշխատի**՝ այնտեղ backend չկա, միայն ստատիկ ֆայլեր։
  Այնտեղ կաշխատի լոկալ երգերի մասը։ Որոնման համար պետք է `server.py`-ը գործարկել
  (տանը կամ որևէ hosting-ում, որտեղ կարող ես env variable դնել)։
