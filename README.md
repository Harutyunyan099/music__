# muzzz

Անձնական երաժշտական web app՝ քո լոկալ ֆայլերը + YouTube որոնում, հավաքածու,
սիրածներ, վերջին լսածներ, մշտական նվագարկիչ և **My Wave** (Моя волна) —
անձնական ալիք, որը կառուցվում է քո իրական լսածից։

Ամեն ինչ աշխատում է քո համակարգչում։ YouTube API բանալին **երբեք** չի հայտնվում
frontend-ում՝ բրաուզերը խոսում է միայն քո սեփական backend-ի հետ։

---

## 1. Արագ սկիզբ

```bash
# 1. բանալին
cp .env.example .env
#    բացիր .env-ը և գրիր՝ YOUTUBE_API_KEY=քո_բանալին

# 2. գործարկում
python3 server.py          # կամ՝ start-windows.bat / ./start-mac-linux.sh
```

Բացվում է `http://localhost:8000`։

Առանց բանալու էլ ծրագիրն աշխատում է՝ լոկալ 20 երգը, հավաքածուն, սիրածները,
նվագարկիչը և ալիքը (լոկալ ֆայլերի հիման վրա)։ Որոնման բաժինը այդ դեպքում
ցույց է տալիս հստակ հաղորդագրություն, ոչ թե սխալ։

**YouTube Data API v3 բանալի ստանալ**՝ [console.cloud.google.com](https://console.cloud.google.com) →
նոր project → *APIs & Services* → *Enable APIs* → **YouTube Data API v3** → *Credentials* → *API key*։

## 2. Ճարտարապետություն

```
Browser ──► /api/search ──► server.py ──► YouTube Data API v3
                              │  (բանալին այստեղ է՝ .env / env var)
Browser ◄── մաքուր JSON ◄─────┘
```

- `.env`-ը `.gitignore`-ում է. բանալին repo չի ընկնում։
- Backend-ը երբեք չի վերադարձնում YouTube-ի raw պատասխանը (այն կարող է բանալին պարունակել)։
  Սխալները թարգմանվում են կարճ կոդերի՝ `no_key`, `quota`, `bad_key`, `network`, `upstream`։
- Պատասխանները cache-վում են 10 րոպե՝ quota-ն չվատնելու համար։

### Backend endpoints

| Endpoint | Ինչ է անում |
|---|---|
| `GET /api/status` | կա՞ բանալի (frontend-ը դրանով է որոշում՝ որոնումը միացնել թե ոչ) |
| `GET /api/search?q=&pageToken=&order=&limit=` | YouTube search.list + videos.list միասին՝ տևողությամբ և դիտումներով |
| `GET /api/videos?ids=` | կոնկրետ video-ների տվյալները |
| ամեն ինչ մնացած | ստատիկ ֆայլեր՝ **Range** headers-ի աջակցությամբ (լոկալ երգերում seek անելու համար) |

## 3. Render-ում տեղադրելը

1. GitHub-ում push արա նախագիծը (առանց `.env`-ի)։
2. Render → **New → Web Service** → ընտրիր repo-ն։
3. Build command՝ `pip install -r requirements.txt`
   Start command՝ `python server.py`
4. **Environment → Add Environment Variable**՝ `YOUTUBE_API_KEY` = քո բանալին։
   Render-ը `PORT`-ն ինքն է տալիս, ձեռքով դնել պետք չէ։

Սերվերը bind է անում `0.0.0.0`-ին և վերցնում `$PORT`-ը, բրաուզեր չի բացում production-ում
(լոկալ բացելը միանում է `OPEN_BROWSER=1`-ով, որը արդեն կա start-սկրիպտներում)։

## 5. Ինչպես է աշխատում My Wave

1. **Signals** — ալիքը կշռում է կատարողներին ըստ՝ սիրածներ (×5) → վերջին լսածներ (×4)
   → հավաքածու (×2) → լոկալ ֆայլեր (×1)։
2. **Ընտրություն** — կշիռներով պատահական ընտրվում է կատարող (վերջին 2-ը բացառվում են՝
   որ նույն artist-ը անընդմեջ չգա), նրա անունով կատարվում է YouTube որոնում,
   արդյունքները cache-վում են 30 րոպե։
3. **Խառնում** — ~25% դեպքերում ալիքի մեջ մտնում է քո լոկալ ֆայլերից մեկը։
4. **Կրկնությունների բացառում** — վերջին 120 նվագարկվածը և skip արածները չեն առաջարկվում։
5. **Ավտոմատ շարունակություն** — երգը վերջանալիս `Player.onEnded` → `Wave.next()` →
   հաջորդը միանում է ինքնուրույն. հերթը միշտ լցված է 4 երգով։
6. **Skip / Don't recommend** — երգը գնում է skipped ցուցակ և այլևս չի հայտնվում։
7. **Դատարկ վիճակ** — եթե ոչ մի signal չկա, ցուցադրվում է onboarding + «Գտնել երաժշտություն»
   կոճակը։ Եթե API-ն անջատված է, ալիքը շարունակում է աշխատել լոկալ ֆայլերով։
8. Ամեն երգի կողքին գրված է՝ **ինչու** է առաջարկվել («Քանի որ լսում ես X»)։
   Ժանր չի հորինվում — YouTube API-ն այդ տվյալը չի տալիս։

## 8. Ինչ պետք է իմանաս

- `.env`, `server.py` և մյուս գաղտնի ֆայլերը սերվերը **չի տալիս բրաուզերին** (404), նույնիսկ եթե
  ուղիղ հասցեն գրես։ Դա ստուգված է։
- **Երգերը չեն ներբեռնվում YouTube-ից։** Նվագարկումը կատարվում է YouTube-ի պաշտոնական
  IFrame Player-ով (embed), ինչպես պահանջում են նրանց կանոնները։ Ձայնի էքվալայզերն
  աշխատում է միայն լոկալ ֆայլերի համար՝ embed-ի ձայնին հասանելիություն չկա։
- Որոշ տեսանյութեր սեփականատերը արգելում է embed անել. այդ դեպքում ալիքը ինքնաբերաբար
  անցնում է հաջորդին։
- YouTube-ի `search.list`-ը արժե **100 quota unit**, օրական լիմիտը լռելյայն 10 000 է
  (≈100 որոնում)։ Դրա համար կա debounce (420ms), cache և pagination։
- GitHub Pages-ի վրա որոնումը **չի աշխատի**՝ այնտեղ backend չկա, միայն ստատիկ ֆայլեր։
  Այնտեղ կաշխատի լոկալ երգերի մասը։ Որոնման համար պետք է `server.py`-ը գործարկել
  (տանը կամ որևէ hosting-ում, որտեղ կարող ես env variable դնել)։

## 9. Ֆոնային նվագարկում և հեռախոսին տեղադրելը

Ծրագիրը այժմ **PWA** է՝ `manifest.json` + `sw.js` (service worker)։

**Հեռախոսին տեղադրել.**
- Android / Chrome՝ բացիր կայքը → ⋮ → *Add to Home screen* / *Install app*
- iPhone / Safari՝ բացիր կայքը → Share → *Add to Home Screen*

Դրանից հետո muzzz-ը բացվում է որպես առանձին հավելված, իսկ նվագարկումը շարունակվում է
էկրանը անջատելուց և ծրագրից դուրս գալուց հետո։ Կողպէկրանին երևում են երգի անունը,
շապիկը և play/pause/next կոճակները (Media Session API), իսկ scrubber-ը ցույց է տալիս ճիշտ դիրքը։

**Կարևոր սահմանափակում.** ֆոնային նվագարկումն աշխատում է **քո ֆայլերի** համար
(`.m4a`-ները և ադմին պանելից ավելացրածները՝ HTML5 `<audio>`)։ YouTube-ից եկող երգերը
ֆոնում կանգ են առնում — դա YouTube-ի embed-ի կանոնն է, շրջանցելը արգելված է
և կարող է բանալիդ արգելափակել։

**Տեխնիկական մանրամասն.** էքվալայզերը երգը անցկացնում է Web Audio-ի միջով, իսկ որոշ
Android-ներ ֆոնում սառեցնում են այդ շղթան։ Դրա համար շղթան կառուցվում է **միայն այն
դեպքում, երբ էքվալայզերն իրոք միացրած է**։ Եթե ֆոնային նվագարկումը քո հեռախոսում
կտրվում է, Կարգավորումներում էքվալայզերը զրոյացրու։

**Offline.** Service worker-ը պահում է ինտերֆեյսը, `songs.json`-ը, շապիկները և լսած
երգերը, այնպես որ առանց ինտերնետի հավելվածը բացվում է և լոկալ երգերը նվագում են։
Որոնումն ու YouTube-ը բնականաբար ինտերնետ են պահանջում։

## 10. Ինչպես է կայքն ինքն իրեն թարմանում

1. **Render → Settings → Build & Deploy → Auto-Deploy: `Yes`**։
   Դրանից հետո ամեն `git push` ավտոմատ նոր deploy է սարքում։
2. Ամեն անգամ, երբ փոխում ես `app.js`, `style.css` կամ որևէ ֆայլ, բացիր **`sw.js`**-ը և
   6-րդ տողում մեկով բարձրացրու տարբերակը՝

   ```js
   var VERSION = 'muzzz-v4.1.0';   →   var VERSION = 'muzzz-v4.1.1';
   ```

   Դա միակ տեղն է, որ պետք է ձեռքով փոխես։ Նոր տարբերակը տեսնելիս հավելվածը
   ջնջում է հին cache-ը և թարմանում ինքնուրույն. եթե այդ պահին երգ է նվագում,
   չի ընդհատում, այլ ցույց է տալիս «Նոր տարբերակը պատրաստ է» հաղորդագրությունը։

## 11. Ֆոնային նվագարկում — ինչն է հնարավոր և ինչը՝ ոչ

**Player-ը մեկն է։** Admin-ի երգերը, YouTube-ի որոնման արդյունքները, հավաքածուն,
սիրածները, վերջին լսածները և ալիքը — բոլորը անցնում են նույն `Player.play()`-ի,
նույն հերթի և նույն Media Session-ի միջով։ Երկրորդ player չկա։

Տարբերությունը **ձայնի աղբյուրն է**.

| Աղբյուր | Ինչով է նվագում | Կողպէկրան | Ֆոնում |
|---|---|---|---|
| Քո ֆայլերը (`.m4a`, ադմինից/Կարգավորումներից ավելացրած) | HTML5 `<audio>` | ✅ | ✅ շարունակվում է |
| YouTube-ի որոնման երգեր | YouTube IFrame embed | ✅ (առջևում) | ❌ կանգ է առնում |

**Ինչու.** YouTube Data API-ն **աուդիո չի տալիս** — միայն որոնման տվյալներ։ Նվագարկումը
պարտադիր անցնում է YouTube-ի embed player-ով, իսկ մոբայլ բրաուզերներում embed-ը
կանգնում է, երբ էջը ֆոն է գնում։ Դա YouTube/Chrome-ի քաղաքականությունն է, ոչ թե
կոդի սխալ։ Աուդիո հոսքը դուրս քաշելն ու `<audio>`-ի մեջ դնելը խախտում է YouTube-ի
կանոնները, կարող է բանալիդ արգելափակել, և այստեղ արված չէ։

**Ինչ արվեց այդ սահմանափակման շուրջ.**
- YouTube երգը ֆոնում կանգնելիս հավելվածը հիշում է վայրկյանը և վերադառնալիս
  ինքնաբերաբար շարունակում է նույն տեղից։
- Կողպէկրանի metadata-ն (անուն, կատարող, YouTube-ի շապիկ) դրվում է նաև YouTube երգերի համար։
- Next/Previous-ը աշխատում է որոնման արդյունքների հերթով (Song A → B → C)։

**Եթե ուզում ես իրական ֆոնային նվագարկում կոնկրետ երգի համար** — ավելացրու այդ երգի
ֆայլը՝ Կարգավորումներ → «Իմ ֆայլերը» → Ավելացնել ֆայլեր։ Ֆայլը պահվում է հեռախոսում
և նվագում է կողպված էկրանի տակ։

## 12. ⋮ Menu, Հերթ և Radio («Երգի նման վալնա»)

Ամեն երգի կողքին (որոնման արդյունք, հավաքածու, սիրածներ, վերջինները, ալիք, playlist)
կա **⋮** կոճակ։ Ներսում՝ Play, Սիրածներ, Հավաքածու, **Ավելացնել հերթում**,
Ավելացնել ցանկում, **Երգի նման վալնա**, Կիսվել։

**Radio-ն ինչպես է աշխատում.** վերցնում է այդ երգը որպես seed և քո backend-ի նույն
`/api/search`-ով անում է մի քանի հարցում (կատարող, «կատարող mix», «անուն + կատարող»)։
Արդյունքները խմբավորվում են ըստ կատարողի և վերցվում են **հերթով՝ մեկ կատարողից մեկական**,
որ մեկ անունը չգերիշխի։ Նույն `videoId`-ն երկրորդ անգամ չի ընկնում (`seen` ցուցակ),
seed երգը չի կրկնվում, 45 վրկ–15 րոպե սահմաններից դուրս տեսանյութերը դեն են նետվում։
Երբ հերթում 3-ից քիչ երգ է մնում, ալիքն ինքն իրեն լրացվում է՝ այս անգամ վերջին
նվագարկված կատարողների հիման վրա, այնպես որ վալնան շարունակական է։

Radio-ն **առանձին player չէ** — դա պարզապես `Player.queue` է `context: 'radio'`-ով։
Next/Previous, Media Session, կողպէկրան, progress — ամեն ինչ նույնն է։

## 13. YouTube երգերի ֆոնային նվագարկում — վերջնական տեխնիկական պատասխան

**Կարճ՝ ոչ, YouTube-ի embed-ով դա հնարավոր չէ, և դա կոդի խնդիր չէ։**

| | Admin/լոկալ երգ | YouTube Search երգ |
|---|---|---|
| Playback source | HTML5 `<audio>` (`player.js` → `playLocal`) | YouTube IFrame Player API (`playYouTube`) |
| Ձայնը որտեղ է | մեր էջի audio element-ում | YouTube-ի iframe-ի ներսում (այլ origin) |
| Ֆոնում | ✅ շարունակվում է | ❌ platform-ը կանգնեցնում է |
| Media Session | մեր էջն է տիրապետում | iframe-ը կարող է վերցնել |

Պատճառը՝ YouTube Data API-ն աուդիո հոսք չի տալիս, իսկ embed-ի ձայնը մեր էջինը չէ։
Մոբայլ Chrome-ը embed-ը կանգնեցնում է, երբ էջը ֆոն է գնում — դա YouTube-ի և
բրաուզերի քաղաքականությունն է։ Շրջանցումը (stream extraction / scraping) խախտում է
YouTube-ի կանոնները, այստեղ արված չէ և չի արվելու։

**Ինչ արվեց փոխարենը (v4.1)՝ ավտոմատ աղբյուրի ընտրություն.**
երբ որոնման արդյունքը համընկնում է քո արդեն ունեցած ֆայլի հետ (անուն + կատարող,
նորմալացված՝ առանց «official video», «feat.» և նման աղմուկի), երգը նվագում է
**քո ֆայլից**, ոչ թե embed-ից։ Այսինքն՝ նույն որոնման արդյունքը դառնում է HTML5 audio
track և ստանում իրական ֆոնային նվագարկում ու կողպէկրան։ Փոխարինումը կատարվում է
միայն վստահ համընկման դեպքում, և օգտատերը տեղեկացվում է հաղորդագրությամբ։

Այսինքն՝ ուզում ես որևէ երգ ֆոնում լսել — ավելացրու նրա ֆայլը
(Կարգավորումներ → Իմ ֆայլերը), և այդ պահից որոնումից էլ այն կնվագի ֆայլից։
